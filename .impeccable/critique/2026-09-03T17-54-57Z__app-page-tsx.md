# Portfolio review — Arnon Chatri

## Bottom line

The application builds successfully and the portfolio has strong raw material, but it is not currently achieving its main goal. The public URL advertised on GitHub is dead, the newest Vercel deployment is authentication-protected, and exact-name Google searches do not show the portfolio. Even after deployment is fixed, discoverability is weakened by the lack of a stable canonical domain, sitemap, robots file, social image, Person structured data, and Google Search Console submission.

The design is warm and personal, but the presentation undersells the engineering work. It looks like a polished beige/amber glassmorphism template rather than a portfolio specifically about computer vision, robotics, embedded systems, and physical AI. The most serious experience problems are unsubstantiated project claims, weak recruiter conversion, public transcript exposure, inaccessible modal/focus/color behavior, and a large AI model downloaded before the visitor asks to use the demo.

## What is working

1. The portrait, Thai and English identity, cream palette, and direct first-person voice create genuine personal warmth.
2. The overall sequence—introduction, about, projects, experience, contact—matches a recruiter’s broad mental model, and the hero has clear Projects and Contact actions.
3. The portfolio contains unusually strong source material: an interactive sign-language project, computer-vision research, and a photographed custom drone.
4. Contact and demo components include loading, success, error, empty, and retry states. The production build and static generation complete successfully.
5. Core name and profile content are present in the server-rendered HTML, which is a sound base once the site becomes publicly crawlable.

## Design specificity

Verdict: **content-specific, visually category-interchangeable**.

The work unmistakably belongs to Arnon, but repeated glass cards, gradient text, generic feature bullets, and broad “AI Engineer | Robotics | System Integration” language make the interface resemble many portfolio templates. The strongest authored moment is the portrait-to-about scroll choreography. The biggest missed opportunity is a clear identity around “AI systems that work in the physical world,” supported by architecture diagrams, experiment results, telemetry, constraints, and measured outcomes.

The warm editorial palette should not necessarily be replaced. It needs a sharper technical layer so the design expresses the work instead of merely decorating it.

## Hierarchy, information architecture, and cognitive load

The macro hierarchy is logical, but the evidence hierarchy is not:

- Featured work is hidden one project at a time inside a fixed `min-h-[960px]` carousel. Visitors cannot quickly scan or compare projects.
- Slides introduce nested vertical scrolling, creating ambiguous scroll ownership, especially on mobile.
- Generic labels such as “Showcase” can be visually larger than the project title.
- “CV & Resume” does not offer a résumé view or download; the main document action is “View Transcript,” reversing recruiter priorities.
- Project prose becomes as small as `text-xs`, while long descriptions, five tags, and five feature bullets weaken scanning.
- Carousel dots show position but not project names or “1 of 3,” forcing visitors to remember what each dot represents.

Cognitive load is moderate: 3 of 8 checklist items fail—chunking, minimal choices, and working-memory support. The five-item navigation is the only decision group above four options; the larger problem is information density inside project cards.

## Priority issues

### [P0] Establish one public, stable production URL

Why it matters: The current advertised URL is dead and the newest deployment is behind Vercel Authentication. This alone prevents the Google goal.

Fix: Link the repository to a production Vercel project, disable deployment protection for Production, assign one stable domain, redirect all aliases to it, and update GitHub/README/profile links.

Suggested command: deployment and domain setup first; design commands cannot compensate for an inaccessible site.

### [P1] Turn projects into evidence, not capability claims

Why it matters: A hiring manager cannot infer ownership, rigor, or impact from phrases such as “production-ready” or “highly effective” without metrics or artifacts.

Fix: Give every project a compact spine: problem, exact role, team/context, architecture, hard tradeoff, quantified result, artifact links, and candid limitation. Show three scannable project summaries before revealing detail.

Suggested command: `$impeccable shape` or `$impeccable clarify`.

### [P1] Fix recruiter conversion and transcript privacy

Why it matters: “CV & Resume” lacks a résumé, yet exposes a transcript containing a student/document identifier and grades. That adds privacy risk without supporting the main hiring decision.

Fix: Make “Download résumé” the primary action. Remove the transcript or publish a redacted version only if it is genuinely valuable.

Suggested command: `$impeccable clarify` and `$impeccable harden`.

### [P1] Repair accessibility and interaction consistency

Why it matters: White text on amber buttons fails normal-text contrast; inputs suppress native outlines; hero social links lack accessible names; modals lack semantics and keyboard focus management; motion is not fully reduced. Carousel buttons stop at the ends while global arrow keys wrap.

Fix: Use accessible color pairs and visible `focus-visible` rings; label icon links; implement dialog semantics, Escape, trap/restore focus, and live regions; honor `useReducedMotion`; make carousel controls follow one navigation model. Increase touch targets to at least 44px.

Suggested command: `$impeccable audit`.

### [P1] Stop loading the AI demo before user intent

Why it matters: `ModelPreloader` runs from the root layout and downloads roughly 15.4 MB of model assets plus a large TensorFlow bundle on every visit. This harms mobile load time, data use, battery, and Core Web Vitals even when the demo is never opened.

Fix: Load the ML runtime and model after “Try Live Demo,” explain camera/download expectations, optimize or replace GIFs, remove permanent `will-change`, and reduce blur/motion costs.

Suggested command: `$impeccable optimize`.

### [P1] Edit all public copy

Why it matters: “Intregration Firmware,” “I’m can work,” “researcher assistant,” and run-on project descriptions make legitimate engineering work feel unfinished.

Fix: Rewrite in concise, active English; quantify outcomes; standardize titles and terminology; either render the existing Thai project copy or remove unused fields.

Suggested command: `$impeccable clarify`.
